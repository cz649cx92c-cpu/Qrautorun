2026-10-13，已接入真实HBVCAM共享视频、实时多码检测、整组位姿计算及校正数据接口。当前相机已由用户确认固定朝下，画面上方对应前进，镜头离地140mm，大致位于车体中心。

## 网页入口

打开 `http://192.168.101.212:3080/?page=camera`，右侧点击 **定位标定**。

1. 选择实际使用的定位板。页面优先选择当前画面识别到的已登记定位板。
2. 点击 **新建采集**。镜头保持固定，移动定位板到画面不同位置，并向两个不同方向倾斜；每次姿态稳定后点击 **采集当前画面**。采集至少16张，建议20～24张。平放在地面上仅平移或旋转的照片无法充分确定内参，程序会拒绝这类退化采样。
3. 核对定位板实际打印尺寸与登记尺寸一致，再点击 **计算并验证内参**。约四分之三照片用于拟合，四分之一独立验证；重投影误差过大、倾角/位置变化不足或焦距异常会拒绝保存。
4. 安装参数已预填离地140mm、前后/左右偏移0mm。0mm为“大致居中”的初始值，尚未当作实测结果。实际测量后填写偏移，确认镜头竖直朝下、画面上方对应车头，再保存。

采集期间保持720P规格和镜头焦距不变。修改焦距或改变分辨率需要重新标定。相机标定时仅移动定位板，不需要驱动车辆。

内参保存至 `config/camera_calibration.json`，安装外参保存至 `config/camera_extrinsics.json`；原照片与登记板几何保存在 `logs/calibration/<采集ID>/`。安装参数及旧内参保留可回滚备份。有效的新文件会被图像桥自动重新加载。

### 照片查看和删除

定位标定弹窗下方的 **已采集照片** 提供缩略图，点击可查看大图；每张右下角的垃圾桶删除单张，**清空照片 → 确认清空** 删除当前采集的全部照片。照片数量及持久化会话同步更新，计算时禁止修改。删除照片不会删除已经保存的内参或安装参数。计算程序只读取会话中保留的照片，避免删除后旧文件意外参与计算；新照片使用唯一文件名，防止覆盖仍保留的照片。

4×4定位板的16个子码不必每次全部露出；当前每张至少要检测到同一板上的4个完整子码，尽量让它们分散在板上。至少16张是不同视角的有效照片数量，不是要求每张检测到16个子码。打印纸须保持平整，可贴在硬板上后向前后、左右倾斜，不能只在地面上平移和旋转。

### 角点方向修正与实测说明

2026-10-13检查发现，官方AprilTag打印图案与OpenCV36h11规范图案的角点起点相差180°。全部587个ID逐一比对确认该差异；已统一重排采集标定和实时检测的角点，保留原PDF、ID及板几何。

用户当前20张真实照片在修正前单张平面对应误差约132px，修正后约0.87～2.53px。**这是单张平面几何检查，不是相机内参拟合或定位精度。** 这些照片的倾角变化仍不足，程序继续拒绝保存内参，没有降低拟合0.8px、独立验证1.2px的门限。原照片未自动删除，需补充不同方向的倾斜视角。

误差单位px表示预测角点与图像中检测角点的像素偏差，不代表厘米。标定被拒绝时不会覆盖已保存的有效内参。

## 真实数据链路

```text
HBVCAM → 原Node共享摄像头服务（单次V4L2采集）
                 ├─ 原网页30FPS预览
                 └─ ROS图像桥15Hz压缩帧 → OpenCV灰度检测
                                            ├─ ID/可见组 → 网页设备状态
                                            └─ 实测内参+安装外参 → 整组PnP
                                                                  ├─ /qr/tags/provisional
                                                                  └─ 时间与局部位姿验证后
                                                                       /qr/tags/observations
                                                                               ↓
                                             已验收二维码地图+局部融合 → 位置/朝向校正
```

二维码只存ID。整组成员的物理尺寸和相对坐标来自登记的PDF布局；整组100mm不会被错用成每个子码黑边100mm。

同组可见成员共同求解板中心和方向，不要求首个子码存活。角点污染通过RANSAC过滤，随后检查重投影、地面法向、距离、平面双解歧义；缺码会增加不确定性，不将更多相关子码简单当作独立高精度传感器。

本机OpenCV4.5.4在接近180°的下视旋转单元输入中出现过IPPE数值异常。已通过反向法线的平面基底求解、有限值检查和迭代回退修正，仍保留地面约束和歧义拒绝。

安装坐标约定：平面导航 `base_link` 的X向前、Y向左、Z=0在地面；相机光学X向画面右、Y向画面下、Z沿镜头指向。画面上方对应前进时，固定旋转为四元数 `[√0.5,-√0.5,0,0]`。该旋转不替代现场安装方向复核。

重启后重新验证IMU约397Hz、局部融合约30Hz与真实多码识别约15Hz。原网页真实预览另存 `logs/legacy-preview-after-handoff.jpg`。浏览器测试依赖改存项目 `.browser-cache/`，避免设备重启清理 `/tmp` 后失效。

## 时间同步与正式准入

当前视频包时间戳为Node收到JPEG的时间，尚未实测相机曝光到该时间的延迟。`camera_stream.yaml` 默认 `capture_timestamp_verified=false`。已准备 `capture_delay_s` 参数，必须用实测延迟与抖动验证后才能填写并启用，不能仅改开关冒充同步完成。

正式检测端使用 `/qr/odometry/local`，不采用未标定的 `/qr/odometry/provisional`。检测完成后短暂缓存结果，等待采集时间两侧的局部位姿进行插值，避免把处理完成时的位置错当作拍摄时的位置。超过时效的结果丢弃。

全局校正将“地图内标记位置+车体系标记位置”换算成拍摄时的小车位姿，再补偿拍摄至最新里程计之间的运动，包括倒车和横移。创新距离、航向和统计门限拒绝错误跳变；协方差使用Joseph更新保持正定。

`covariance_calibrated=false` 时，全局定位只发布 `/qr/localization/provisional`，不发布正式 `/qr/localization/pose` 或map→odom。地图未实测验收时拒绝启动。没有可用同步观测时不会自动加载旧示例地图、猜测位置或开启驾驶。
