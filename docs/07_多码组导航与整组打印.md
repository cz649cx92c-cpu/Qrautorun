# 多码组导航与整组打印

2026-10-14。1×1～6×6表示**一个定位组内部的AprilTag阵列**；整组尺寸指整个正方形阵列的边长（包括完整白色静区与内部间隔），不是单个子码尺寸，也不是每页排版。外购专用AprilGrid标定板使用[独立标定参数](13_专用标定板与6乘6.md)，不套用本页固定打印间距。

## 打印

网页“二维码 PDF”提供组内规格、整组尺寸、生成组数、起始子码编号。默认2×2、140mm整组、3组；每组有4个独立ID，3组共12个子码。

每页A4打印一整组，按100%实际大小打印。组编号B000/B004/B008等位于阵列外，成员编号列表也在有效图案外。整组贴放，成员相对位置不能拆散改变。旧版“每页4码”的PDF不会自动成为已注册定位组，应使用本版重新生成的完整组PDF。

- 1×1至6×6最小整组尺寸分别20、27、42、56、71、85mm；最大180mm。
- 组间隔内部固定2mm；每个子码黑边根据整组尺寸自动计算：`(整组尺寸 - (N-1)×2) / N / 1.25`。
- 140mm整组时：1×1子码112mm、2×2子码55.2mm、3×3子码约36.27mm、4×4子码26.8mm、5×5子码21.12mm、6×6子码约17.33mm。
- ID范围0–586且全局唯一，组数受实际剩余子码数量限制；从0开始时4×4最多36组、6×6最多16组（均为576个子码）。
- 下载成功后持久化每组的成员ID、黑边尺寸和相对位置。相同布局可以重印；不同尺寸/规格不得覆盖已经注册的同一成员ID，需更换起始编号。

## 扫描与定位

ROS2检测器从已注册布局获取每个子码的真实尺寸，使用标定图像与摄像头外参计算相对位姿。对每个有效子码执行：

`base→group = base→member × inverse(group→member)`

因此首个子码损坏，其他成员仍可得到同一个组中心。组内多码必须互相一致才融合；不同组不混合。两个码互相矛盾时拒绝该组，多码中异常成员只有明确一致多数时才剔除。

剩余码少时不确定性增大，不能简单用识别次数或平方根除法虚假提高可靠性。没有有效码时不生成组位姿。实时定位及导航继续检查误差、时效和原有底盘安全条件；退化到不可靠时停车，并非任何破损程度下都保证继续运行。

## 地图和任务

- 地图记录组中心，一个Bxxx对应一个逻辑节点，其数值ID等于首个成员ID；成员不再是独立路点。
- 扫描开始时固定已注册组布局快照；观测布局不同、子码不属于此组或置信度不合理时拒绝导入。
- 同一组不同帧看到不同成员，仍累计到同一个组，不重复创建节点或重复触发任务动作。
- 优化使用组中心观测，保存地图时包含完整`groups`几何，供全局定位读取。正式扫描地图需要至少3个不同定位组，便于现场坐标验收。
- 实测验收测量组中心坐标，表单组中心ID填B编号的数字部分，例如B004填4。
- 前进、倒车和横移控制继续读取融合后的车体位姿；原底盘控制程序、CAN协议、手柄接管均未修改。
- 页面显示识别组数、可见子码数量以及完整/部分可见状态；不再手工填写子码尺寸。
