# 二维码静止地图锚定

已登记定位板在地图中有位置和角度，相机安装外参提供板相对小车的位姿。
两者相减可得到小车的地图位置与朝向，不需要 IMU 提供绝对朝向。
局部底盘反馈和 IMU 再提供连续的运动增量。

本次接入保持实体执行关闭，现成运动模块不变。相机当前仍使用接收时间，
没有将 `capture_timestamp_verified` 或 `covariance_calibrated` 改为已验证。
在底盘真实连续静止、局部融合数据新鲜、已登记定位板几何匹配时，
静止观测可建立地图坐标；运动中不使用这种接收时戳观测作实时二维码校正。

局部融合恢复并改变原点时，旧地图锚定失效，必须根据新的静止观测重新建立。
只看到子码但板中心计算或注册几何不通过，不建立地图位姿。

输出接口：

- `/qr/localization/static_pose`：静止二维码地图位姿，供网页显示位置和朝向。
- `/qr/localization/status`：来源、地图 ID、局部原点、静止状态及实际就绪状态。
- `/qr/localization/provisional`：锚定后的地图位姿及底盘/IMU增量传播。
- `/qr/localization/pose`：原有正式同步路径，仍受实际同步与协方差配置约束。

网页将静止定位明确标注并显示地图 X/Y 与朝向，数据过期或车辆运动时不继续画旧的静止位置。
静止地图位置不会替代运动导航准入条件。

启动及停止只作用于本项目定位服务：

```bash
python3 scripts/service_manager.py start localization
python3 scripts/service_manager.py status localization
python3 scripts/service_manager.py stop localization
```

启动时核对地图文件与数据库最新版本、接纳证据和内容摘要；
复用当前局部融合与相机观测，不创建底盘控制器或重复 EKF。
配置默认关闭 TF 发布，不争用原工程坐标变换。
