# 实时摄像头预览

设备为本次接入的 HBVCAM，USB `0bda:5846`。使用 `/dev/v4l/by-id/usb-Generic_HBVCAM_Camera_200901010001-video-index0`，不按可能变化的 video 编号猜测设备。启动前校验 USB 厂商和产品编号。video-index1 是元数据节点，不用于画面采集。

## 网页操作

- 直接打开 `http://192.168.101.212:3080/?page=camera`，或点击“摄像头预览”。
- 默认1280×720、30 FPS；可切换640×480、30 FPS。
- 提供中心十字线、原尺寸查看、全屏和保存照片。
- “扫描建图”页提供“地图 / 实时画面”切换；开始扫描、继续补扫、恢复正在扫描的记录时自动显示实时画面。

本次用户说明 HBVCAM 并非导航摄像头，因此仅接入实时预览。它没有被自动当成已标定的二维码检测输入，也不使定位/实体控制条件变成已就绪。扫描原始观测继续通过既有 ROS2 同步观测接口写入。

## 实时性

Node.js 调用系统 FFmpeg，采集摄像头原生 MJPEG并直接传输，无二次视频编码。浏览器用 WebSocket 二进制帧和 Canvas显示。

每个浏览器只允许一帧等待显示确认；其余时间保留最新帧，慢客户端不积压历史视频。超过500ms的旧帧不显示，800ms没有更新则清空画面并显示中断状态。浏览器后台/关闭页面释放订阅；最后一个观看者离开后停止采集并释放设备。

界面“传输与显示”计时起点为服务器收到压缩帧，包含网络、解码和绘制；通过往返消息估计浏览器/服务器时钟偏移。它不包含相机曝光和设备内部处理，不是光学端到端延迟。实际局域网结果应以使用设备上的状态为准。

## 配置与启动

新增配置 `config/camera_preview.json`，推流 `web/backend/src/camera.ts`，界面 `web/frontend/src/components/CameraPreview.vue`，入口在 `App.vue`和`server.ts`。Web启动后按观看需求采集，不额外启动 ROS2摄像头节点。

```bash
cd /home/orangepi/ugv/QRautorun/qr_navigation_ws
npm run build
./scripts/start.sh
./scripts/stop.sh
# 真摄像头检查，使用内存扫描记录，不发运动命令
QR_CAMERA_TEST=1 PLAYWRIGHT_BROWSERS_PATH=/tmp/qr-playwright npx playwright test --grep '真实HBVCAM'
```

接口：`/ws/camera`、`GET /api/camera/status`、`POST /api/camera/profile`。依赖系统 `ffmpeg`、`v4l2-ctl`，网页和后端仍为 TypeScript。

参考：[FFmpeg V4L2](https://ffmpeg.org/ffmpeg-devices.html#video4linux2_002c-v4l2)、[WebSocket 缓冲量](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/bufferedAmount)。
