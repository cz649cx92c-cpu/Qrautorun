# 26 · v8 自用版、切图即生效与二维码间连续纠偏

分支：`v8`（基线 `v7` = `700459c`）。本文只描述本分支已落地并有测试或现场日志支撑的内容；
未实测的项目在文末单列，不作为已完成能力。

本版**没有**改动：地图坐标、既有路径与任务快照、`calibration.db`、相机内参/外参、
IMU 标定数据、底盘运动学参数。

---

## 1. 自用版界面简化

QRautorun 是内部自用工具，v8 去掉了商业化流程带来的必填项和大块说明区：

- 删除「实验员/用户姓名」字段及其必填校验。
- 扫描记录名、路径名改为自动生成（`扫描-YYYYMMDD-HHmm`、`地图名+新路径`），不再让操作员手填。
- 删除顶部阶段流程图、右侧「作业概览」、以及整块「使用指南」页面。
- 保留：地图/路径选择与新建、二维码点位、编辑路径、开始/暂停/停止、错误提示。

**没有**放宽任何底层安全门。自用版只是把「两步人工确认 + 大段说明」压成一行状态，
后端 `mapId/mapVersion` 隔离、`draft` 地图拒导航、定位/相机/IMU/底盘条件检查一行未改。

## 2. 切换地图即生效，删除「启用此地图」按钮

**v7 的问题**：定位作用域被"这张图的坐标是否已验收"卡死。实测 `POST /api/localization/map`
对 `coordinateStatus=draft` 的地图直接 400，前端 watcher 又要求「已选任务 + accepted」才发请求，
于是切到办公室9/8 后定位仍锚在旧图，界面只能显示"当前定位属于其他地图"并永久卡住。
`maps/office-confirmed.json` 的 mtime 与定位日志停在同一个时间点，之后长时间零成功零报错。

**v8 的做法**：定位作用域跟随「当前选中的 `mapId + mapVersion`」。

- `web/backend/src/server.ts`
  - 新增 `localizationScopeBlock()` / `localizationScopePhase()` 纯函数，
    phase 取值 `unknown | switching | waiting-anchor | anchored`，导航放行与前端状态共用同一套口径。
  - `POST /api/localization/map` 允许 `draft` 地图切换（保留"小车静止"门），
    返回 `coordinateStatus / reviewed / switched`，并在审计日志里标注
    「坐标来自扫描：未做人工验收」。内容未变时不写文件，避免抖动。
  - 新增 `GET /api/localization/scope`。
  - `/api/navigation/start` 去掉人工 `mapApproval` 门禁，改为对所有 `routeMode`
    统一校验 `mapId + mapVersion + poseAvailable`，不匹配返回 423。
- `localization.py`：`reload_map` 接受 `draft` 地图并清空 history/estimate/covariance/anchor；
  `navigation_ready` 不再依赖 `coordinate_reviewed`（字段保留用于状态展示）。
- `scripts/start_localization.sh`：预检区分是否已验收，未验收仍可启动（否则重启即失去定位）。
- `web/frontend/src/App.vue`：删除「启用此地图」按钮与相关手动确认 UI，
  地图下拉切换后立即设置作用域并触发既有切图重锚；新增「当前地图 · 名称 v版本」状态条。
  路径只能加载当前 `mapId + mapVersion` 的快照，不匹配拒绝。

**旧接口保留兼容**：`/api/maps/confirm`、`/api/maps/accept` 仍在，只是前端不再要求点击。

## 3. 相机预览 180° 与时序标定指纹解耦

**v7 的问题**：`camera_preview.json` 加上 `rotate: 180` 后，时序标定按**整文件 SHA256** 校验，
指纹失配导致 `captureTimestampVerified=false`，导航门禁里的「实时标定相机观测」永久不 ready。
旋转只影响预览图像方向，不改变采集时间戳、分辨率或帧率。

**v8 的做法**：

- `timing_calibration.py` 新增采集配置指纹 `capture_fingerprint()`：
  只纳入影响采集与时序的字段（device、vendor/product、分辨率、fps、曝光/采集模式等），
  明确排除 `rotate / hflip / vflip / preview` 等纯显示字段；`camera_calibration.json`、
  `camera_extrinsics.json` 仍按严格整文件校验。
- 旧证据继续走 `legacy-capture-spec` 分支，**不重跑**运动时序标定。
- `scripts/calibrate_motion_timing.py` 写入 `configurationCaptureSha256`。
- `web/backend/src/camera.ts` 新增 `cameraVideoOptions(rotate)`：
  `0 → -c:v copy`，`180 → -vf hflip,vflip`（只允许 0/180，因为其它角度会改变帧尺寸）；
  预览方向不再影响检测、建图与标定。

## 4. 二维码区间执行链路

v7 的区间执行只有「到码停稳 → 确认档位 → 走下一段」。v8 补齐了起点判定、
转向残差、边界横向对中，以及二维码之间的连续估计。

### 4.1 起点门禁（`start_gate.py`，新增）

纯函数模块（不依赖 ROS），用于替换"直接拿上一帧位姿判断"的做法：

- 等待**当前地图、当前 epoch** 的新鲜稳定样本（默认 5 个样本、抖动 ≤10 mm / ≤0.5°）；
- 起点偏差按第一段的**沿程 / 横向**分解计算，而不是欧氏距离——
  车沿路线方向稍微靠前/靠后但横向居中，应当放行；
- 保留原有横向（`max_cross_track_m`）与航向门限；
- 超时（默认 12 s）内没有有效定位则明确拒绝并说明原因。

### 4.2 转向残差标定（`turn_calibration.py`，新增）

只读打开 `calibration.db`（`mode=ro`，运行期绝不写标定库），从有效的、方向一致的转向试验里
推导两个有界控制输入：`acceptance_deg`（默认 ≤2.5°）、`correction_tolerance_deg`（默认 ≤1.0°）。
反向/不匹配/无效试验一律排除，避免"上一次右转异常"变成控制目标。无可用分析时回退固定默认值。

### 4.3 边界横向对中（`CENTER_ALIGN / CENTER_MOVE / CENTER_STOP`）

每个二维码停稳后，相对**下一段目标直线**计算有符号 cross-track：

| 条件 | 行为 |
| --- | --- |
| `abs(cross) ≤ 2 cm` | 直接进入下一段 |
| `2 cm < abs(cross) ≤ 5 cm` | 低速、有限 crab 对中，收敛到 ≤2 cm 后停稳再进下一段 |
| `abs(cross) > 5 cm`、方向发散、航向/速度异常、定位质量低、超时或距离窗口耗尽 | 明确 FAULT 停车 |

- 路线仍是横平竖直，不生成弧线，不把横移伪装成前进；
- 第一段起点的偏差不会被混进后续区间；
- 结构记录 `centering.startCrossM / endCrossM / deltaCrossM / direction / command / travelM / durationS / decision`。

现场基线（办公室9 v5，4 段）：

- 对中上线前 17:43 那次运行：`+25.7 / -27.0 / +21.7 / -23.4 mm`，系统只记录不修正；
- 对中上线后 19:39 那次运行：`+12.1 / -19.4 / +15.3 / -15.4 mm`，
  四段都小于 2 cm，因此按新逻辑直接进入下一段，没有实际进入 CENTER 相位。

也就是说：**对中逻辑已生效但尚未在真实偏差 >2 cm 的工况下被实车验证**。

### 4.4 二维码间 dead-reckoning（`deadReckoning`）

每个直线 `MOVE` 区间建立 DR 状态，用底盘轮速 `vx/vy` 与 IMU `yaw/yaw_rate` 按时间积分，
实时得到预测位姿、预测有符号 cross-track 与航向误差，而不是只在 `END_STOP` 才算偏差。

- 预测横向偏差达到 `dr_correction_trigger_m`（默认 0.008 m）时，
  进入 **DR 来源**的 `CENTER_*`，用已有 crab 能力低速有限纠偏；
- 纠偏期间继续积分 DR，否则预测偏差不会随实际横移收敛；
- 纠偏不改变目标里程，不生成弧线，不把横移伪装成前进；
- 二维码重新出现时，按 pose stamp 变化调用 `dr_try_rebase()`：
  - 记录 QR 前最后一个 DR 位姿、QR 绝对位姿、横向/沿程/航向残差、校正前后值；
  - 只接受**当前地图 + 当前 epoch + 质量合格 + 时间戳有效**的 QR；
  - 跨地图、epoch 变化、sigma 超限、低质量 → `skipped_map_or_epoch` / `skipped_low_quality`，
    单帧低质量跳变不会直接当车辆偏移；
  - 校正只重置 DR 锚点/误差状态（`pred / anchor_pose / anchor_stamp / anchor_cross`），
    **不瞬移控制位姿**；
- QR 与预测的残差连续超过硬限（默认 5 cm、连续 3 帧）→ 判定预测发散并 FAULT 停车。

相关参数（`node.py` 默认值，可在 `config/navigation.yaml` 覆盖）：

```
dr_correction_enabled, dr_cross_target_m=.008, dr_correction_trigger_m=.008,
dr_correction_limit=2, dr_correction_travel_m=.05, dr_correction_min_remaining_m=.15,
dr_correction_min_stale_s=.25, dr_rebase_residual_limit_m=.05,
dr_rebase_max_sigma_m=.03, dr_divergence_frames=3
```

`0.008 m` 是**控制目标**，不是已达到的实车精度。可引用的实测横向偏差仍是上一节的 12–27 mm 量级。

### 4.5 诊断

`execution_diagnostics.py` 新增结构化输出：

- `deadReckoning`：`active / decision / predictedPose / predictedCrossM / predictedHeadingDeg /
  staleS / anchorStamp / crossTrackTargetM / correctionCount / qrCorrectionResidual / corrections`
- 继续输出 `centering`、`centeringHistory`、`turnExit`、`localizationJump`

`web/backend/src/robot.ts` 的 zod schema 同步扩展 `centeringHistory`、`deadReckoning`
及 `decision.centeringTriggerM / centeringDoneM`，**不新增任何用户按钮**。

## 5. 地图实时车体图标按真实外形绘制

v7 的实时车体直接用 `map.vehicle`（设计占位包络 `length 0.8 m × width 0.4 m`，还带 `margin`），
画出来比实车大一倍左右。

v8 在 `web/shared/model.ts` 新增**显示专用**常量：

```ts
export const vehicleFootprintM = {length:0.46,width:0.36} as const;
```

`MapCanvas.vue` 的实时车体改为按该米制尺寸乘世界单位（100 px/m）绘制，随地图缩放一起缩放：

- 没有固定像素下限、没有固定像素膨胀，低缩放下不会被"顶"到最小像素；
- 锚点仍是 `base_link`（矩形以 group 原点为中心），航向取 `yaw`，长轴沿本地 `+x`（前进方向）；
- 航向指示条终点收在车身轮廓内，描边不会把轮廓撑大；
- `map.vehicle` 仍是**规划/安全包络**（参与 `validate()` 的行宽余量和退出距离校验），
  两者故意分开；0.46 m 是整车外形长度，**不是轮距/轴距**，底盘运动学、定位、IMU、相机均未改动。

## 7. 尚未验证 / 已知限制

- **dead-reckoning 提前纠偏没有实车数据**。代码、参数、诊断和单元测试已就位，
  但还没有一次真实运行在偏差达到 8 mm 触发阈值的工况下进入 DR 纠偏。
- **边界对中尚未在 >2 cm 工况下实车验证**（两次现场运行偏差都 <2 cm）。
- **QR rebase 的残差统计只有单元测试**，没有真实"二维码重新出现"的现场样本。
- `tests/test_segment_execution.py` 的 3 个既有失败未修复。
- 前端 `web/frontend/dist/` 是 2026-10-22 20:32 的构建产物（含 dead-reckoning 的后端 schema 变更），
  **不包含**第 5 节的车体图标改动；车体图标目前只在源码层，需重新构建并授权部署后才会出现在页面上。
- 定位精度、标定合规性等结论一律以现场实测日志为准，本文件不给出未测得的精度承诺。
